# 志愿服务管理平台

FastAPI + SQLAlchemy（PostgreSQL）+ Redis + Vue3 / Element Plus / ECharts（Vite 构建）。
覆盖「活动发布 → 青协审批 → 报名（即选即得 / 报名后筛选）→ 候补流转 → 一键分配 →
扫码签到签退 → 时长核准与锁定」全链路。

## 一、快速启动

统一用 Docker 跑（后端依赖 PostgreSQL 与 Redis 两个服务，不再支持本机直跑）。

```bash
cp .env.example .env          # 填 POSTGRES_PASSWORD、RUCVA_ID_CARD_KEY
docker compose up -d --build                    # postgres + redis + backend + web + cloudflared
docker compose --profile seed run --rm seed     # 重置演示数据
docker compose --profile test run --rm tests    # 跑回归测试（独立的 rucva_test 库）
```

- 入口 **http://127.0.0.1:8080**（nginx 托管前端并同源反代 `/api`，无跨域）。
- 数据库 5433 / Redis 6380 / 后端 8000 都只绑 `127.0.0.1`，调试用得上、公网碰不到；
  对外只有 web 的 8080 与 cloudflared 隧道。
- cloudflared 固定域名隧道：token 存 `.env` 的 `CLOUDFLARE_TOKEN`，公网域名在
  Cloudflare Zero Trust 控制台绑定，`docker logs rucva-cloudflared` 看连接状态。
- 上传的活动二维码存命名卷 `rucva_uploads`，数据库存 `rucva_pgdata`。
- 启动时 Redis 与身份证加密密钥都是**硬依赖**：连不上、密钥不对直接起不来——
  半可用的服务比起不来更难排查。

### 环境变量（.env）

| 变量 | 说明 |
|---|---|
| `POSTGRES_PASSWORD` | 数据库口令，必填；公网部署务必改掉示例值 |
| `RUCVA_ID_CARD_KEY` | 身份证号的加密密钥，必填。**必须与数据库分开保管**，否则加密只是走过场；换密钥等于已有数据读不出来（先解密导出再重新写入） |
| `RUCVA_DEMO_PASSWORD` | 内测登录共享口令。**留空则整个演示登录接口不存在**；SSO 接通后必须留空 |
| `RUCVA_PUBLIC_BASE_URL` | 平台对外网址（多个用逗号分隔）。二维码里写的就是它，只有列在这里的域名才允许出现在码里 |
| `RUCVA_EXPOSE_DOCS` | 设为 `1` 才暴露 `/docs` 与 `/openapi.json`，默认关闭 |
| `RUCVA_TIANDITU_TK_SERVER` | 天地图**服务端** tk：管理端地图瓦片转发 + 地名搜索。要在天地图后台登记服务器公网出口 IP；只在后端用，不进前端 |
| `RUCVA_TIANDITU_TK` | 天地图浏览器端 tk，仅作瓦片转发的兜底（服务端 tk 没配时，后端带 `RUCVA_PUBLIC_BASE_URL` 当 Referer 去取）。两把都空 = 地图只显示坐标 |
| `RUCVA_TIANDITU_DAILY_LIMIT` | 每天向天地图取瓦片的上限，默认 10000（天地图给的额度），到上限直接 503 |
| `CLOUDFLARE_TOKEN` | 隧道令牌，勿提交/外传 |
| `WEB_/BACKEND_/POSTGRES_/REDIS_HOST_PORT` | 宿主机端口，被别的项目占用时改这里 |

### 登录方式

学校统一身份认证（微人大，走 CAS 服务器上的 OAuth2.0 接口）是唯一正式入口，
参数在「集成设置」页配置。
接通之前，开发小组用 `POST /api/auth/demo-login`（学号 + `RUCVA_DEMO_PASSWORD` 共享口令）
登录；口令连错 10 次锁该来源 IP 5 分钟。`GET /api/auth/sso-mode` 会如实告诉前端当前是
哪种情形（演示登录 / SSO 已接通 / 两者都没有、谁也进不来）。

会话 24 小时过期，令牌只认 `Authorization` 头，**唯一的例外是导出与材料下载**这一个直链
场景：前端先换一张一次性票据（绑那一个网址、60 秒有效、用一次即作废），地址栏里因此
永远不会有会话令牌。

## 二、权限体系

权限是三层叠加的，各管一段：

| 层 | 载体 | 说明 |
|---|---|---|
| 身份 | `User.roles`，可多个 | `admin` 管理员 / `qingxie` 青协 / `initiator` 活动发起方 / `student` 学生。顶栏切换视角；路由守卫在视角不够但持有对应身份时自动切换放行 |
| 类型 | `User.user_type`，二选一 | `teacher` / `student`。**老师类型不参与志愿报名**（自主报名与管理员补录均拦截），也不用补充个人信息；老师首次登录即自动获得 `initiator` 活动发起方身份，学生获得 `student` |
| 青协层级 | `User.qingxie_post` | `council` 会长团（除集成设置外与管理员同权）/ `head` 部长 / `core` 部门骨干 / `member` 部门成员 |
| 活动级 | `activity_managers` | 谁能看、能操作哪个活动（见下） |

**部门成员是「学习权限」**：平时就是来报名的学生，切到青协视角能进工作台、能看，
但**任何写请求都在依赖层被拦**（试算类接口除外，导出也禁）。拦在依赖里而不是各个接口里，
是因为管理端写接口有五十多个，逐个加判断必然漏。

| 页面 | 可见身份 |
|---|---|
| 数据总览 dashboard | 管理员、会长团 |
| 集成设置 integrations | 仅管理员 |
| 志愿者档案 users | 管理员、会长团、部长 |
| 活动审批 approvals | 管理员、会长团、部长；对外联络部的部门骨干（有值班资格） |
| 角色管理 roles | 管理员、会长团、部长；部门骨干进来只为认领本部门成员 |
| 活动管理 manage | 管理员 / 活动发起方 / 青协 三个视角 |
| 审计日志 audit | 同上；管理员与会长团看全部，其余只看自己管理的活动 |
| 个人页（广场 / 我的报名 / 时长） | 仅学生视角；工作台视角访问自动跳回活动管理（消息中心两种视角都能进） |

活动多人共管（`activity_managers`）：创建者自动成为管理者且**不可被移除**；管理者之间
权限完全相同、可互相添加/移除，但**不能移除自己**；被添加者必须持有活动发起方/青协身份；
管理员无需添加、天然可见全部。部长另外能看到本归口部门的全部活动；部门成员看到的范围
**跟着自己归属的那位骨干**——成员是跟着某个人学做事的，不是跟着整个部门。

### 对外联络部：值班、志愿北京登记、立项书（`backend/liaison.py`）

二级志愿团体的活动都归口对外联络部，审批量远超其他部门，所以只在这个部门（按部门名认）启用值班；
其他部门的审批行为不变。

- **值班**：同一时间一人，只能是本部门的**部门骨干或部长**。部长（及会长团、管理员）在「活动审批」
  页指定或撤下；在班的人自己交给另一位骨干/部长。交接留流水（谁、从谁、交给谁、何时、备注）并写审计。
  值班人被调离部门或降为成员，值班自动失效。
- **审批路由**：提交/转交到对外联络部、时长锁定与解锁申请、审批超时催办，通知**只发值班人**
  （没人值班才发部长）。审批人仍挂部长，值班人与部长都能处理本部门
  的活动审批（通过/驳回/转交）与时长审批；转给会长团之后部门不再插手。
- **时长审批通知**（所有部门）：锁定与解锁申请逐条**只发归口部门的对接人**（有值班人发值班人，
  否则部长），不再逐条抄送会长团与管理员——他们照样能在「活动审批」处理。找不到对接人（部门没设
  部长）才兜底发会长团。提交后 24 小时（`APPROVAL_REMIND_HOURS`）仍未处理，催对接人并抄送会长团，
  每条只催一次（`HoursRequest.reminded_at`）；永不自动通过。
- **值班日报**：每晚 21:00 给部长一条当天汇总（今日新增 / 今日处理 / 尚未处理，含志愿北京登记），
  三栏都空不发；用一条条件更新占下当天日期，清扫多轮、换主、重启都只发一次。
- **志愿北京登记**（每个活动不限条数）：管理者在志愿北京建好活动后登记名称 → 通知值班人；值班人
  （或部长、会长团、管理员）上志愿北京核对后通过/驳回，结果通知登记人。登记错了由管理者作废再报。
  与时长审批暂不挂钩。
- **立项书 / 盖章立项书**：活动管理「审核」页签，只有活动管理者能传，每格只留一份（传新即替换，
  旧文件删除，上传写审计），下载只给管理者与审批线上的人（值班人、部长、会长团、管理员）。
  - 立项书：**提交对外联络部审批必须有**；审批中可以换，通过后不能再换；**被驳回即作废**（连文件删掉），
    重新提交要传新的一份。转进对外联络部却没有立项书的，不能通过。
  - 盖章立项书：只用于对外活动（归口对外联络部），时长锁定前随时可换（审核中、已锁定不能换）。
    **手动提交时长审核必须有**；申诉期满的自动提交遇到缺它就不提交，只提醒管理者一次，补传后下一轮
    清扫照常提交。
  - 志愿北京时长录入截图：**所有活动**（不分内外）时长锁定后都要传，见第五节；只收图片/PDF，
    只能在「待录入志愿北京」时传与换，活动已完成后不能再换（要改先申请解锁时长，截图随之作废）。

## 三、岗位模型（场次 → 岗位）

结构：Activity ─ Shift（场次：起止时间）─ Position（岗位：职责、名额、条件）。

- **时间只存在于场次这一层**，岗位没有自己的时间。场次是时段冲突检测的单位，
  同场次内的岗位互斥（一人一场次只占一个岗位），所以换岗不会产生新的时段冲突。
- 场次两种模式：`pick` 报名即选岗位（运动会）；`assign` 报名只锁时段，截止后由
  一键分配统一分工位（图书整理周）。`assign` 场次建场时自动带一个**占位岗位**装
  「还没安排的人」，一键分配只往真实岗位里排，排不下的自然留在占位岗位里。
- 培训 / 彩排也是场次，只是**附属**于某个服务场次（`parent_id`）：报名主场次时连带
  报上、退选时连带退，自己不设名额。这样签到码、到岗大屏、时长计算、冲突检测全部
  原样复用。附属场次可以指定只对某几个岗位生效（东门组周五彩排、检录组周六彩排）。
- 条件要求按标签匹配志愿者档案，可选标签就五个：性别 / 学院 / 年级 / 校区 / 学段。
  场次与岗位各能设一套（`requirement_tags`），报名时直接拦截，一键分配时同样作为硬约束；
  活动层另有「招募范围」限定校区与学段，整个活动一刀切。**认识不了的标签不拦人**——
  一个错别字不该把所有人挡在外面。岗位另外有三段给志愿者看的文字
  （服务任务 / 岗位要求 / 培训内容）与服装、报酬说明。
- 同一场次里组名相同的岗位共用一名组长。

## 四、报名 / 候补 / 名额

- 招募模式两种：`instant` 即选即得（名额满自动进候补）/ `screened` 报名后筛选
  （填报名问卷、勾意向岗位，报名截止后由管理者逐人或批量录取）。
- 冲突检测**只比场次时间区间、跨活动**：与本人所有活动的有效报名区间重叠即拒绝
  （409 附冲突明细）。**候补中的场次同样算已占用时段**——排了队就等于预留了这段时间。
- 每个场次各自算截止：`min(活动报名截止, 本场次开始时间)`，开场即不收人。
- 名额只有岗位上这一个来源。已消耗 = `enrolled` + `pending_confirm` + `seat_held`。
  容量判断与落库整段持场次锁串行化，配合 `enrollments` 的部分唯一索引，
  杜绝抢报瞬间的超卖与重复报名（见 `backend/locks.py`）。场次锁是 Postgres 的
  事务级咨询锁，拿在请求自己的会话上、随事务提交/回滚释放（没有租期，不会
  「活还没干完锁先过期」）；每个进程最多 `RUCVA_LOCK_SLOTS`（默认 5）个请求
  带着连接去数据库排队，其余在进程内等，不占连接池。前面再挡一道 Redis 名额闸门，
  抢不到号的请求一次 Redis 往返就回「满了」。
- 抢报压测：`scripts/rush_bench/`（300 人抢 200 名额 + 50 候补，另有 20 人刷页面），
  用法见其中 `run.sh` 开头。数字只做同一台机器上的前后对比。
- 满员进候补队列（按报名时间排序）。有人退选释放名额 → 队首转正 `pending_confirm`，
  开 **2 小时确认窗口**，夜间 23:00–8:00 不计时（22:30 转正 → 次日 9:30 截止），
  且不晚于场次开始（清扫协程 + 惰性判定双保险），超时记一次「放弃」并顺延下一位。
- 开始前 **24h 内退选**（且报名已截止）：该名额被**扣留**（`seat_held`）——不释放给候补、
  不回到公共名额池，本人也无法再报同一场次。防止有人临期退了、别人补进来、再退一次，
  把现场人数搅乱。临期退选会被记录，供青协在档案里查看。
- 报名时可勾选**是否接受岗位调剂**（`allow_reassign`），随时可改。这只是给管理者的参考：
  名单、分配面板与导出表都会显示，管理者仍可调换工位，但违背本人意愿的调换会连同
  姓名写进留痕。

**平台不对志愿者做任何限制**：没有准入名单，不拦任何人报名，也不冻结任何东西。
违规记录（迟到早退 / 无故请假 / 无法取得联系 / 消极志愿 / 其他）只是归档，青协在志愿者档案里
看得到；「提示分」是给青协内部看的参考值，实时算出来，低于 60 只在名单上挂一个感叹号，
不产生任何后果。算法：100 分起，三项都按活动计——每条违规按类型扣分；一个活动里有临期退选
扣一次（退几个场次都只扣一次）；一个活动签到过（含管理者补签）、没有违规也没有临期退选，
等他报的场次都结束后加 5 分。所有加扣按时间顺序逐条累计，每一步都夹在 0～100 之间，
满分时加的分不会存起来抵后面的扣分；档案里按时间列出每一步。

## 五、签到签退与时长

- 同一签到码：**第一次扫=签到、第二次扫=签退**、已签已退再扫拒绝；仅本场次已报名
  （`enrolled`）的志愿者有效。任务两种：整场次一个统一码，或每个岗位一个独立码；
  可签时段默认取场次起止各外扩 30 分钟（提前到岗与拖堂散场都签得上）。
  二维码 SVG 直达落地页 `/#/checkin/{token}`；管理端实时大屏（前端 5s 轮询）
  显示到岗/离岗率。
- 签退没有另外的宽限：签到、签退都只在签到码的**可签时段内且码开着**时能自己做。
  这一场已经没有能用的码（过了截止，或被关掉/删掉）时还没签退的，由系统**按场次结束时间兜底**
  （auto 标记）；码还开着没过截止的记为时长待定（pending）。两类都标为**待核**，需管理者
  逐条核对数值后单独确认——到场扫个码就走的人会和全程服务的人算出一样的时长。
  兜底是每次现算的：关掉的码重新开、或把截止往后改，没签退的人又回到待定。截止必填，
  管理端把截止设得早于场次结束、或在场次结束前关码，都会先弹确认说明这个后果。
  管理者手动补签/签退不受码的时段限制。
- 时长认定按场次的 `hours_mode` 三选一：`checkin` 签退−签到 / `fixed` 到场即按场次时长 /
  `none` 只记出勤不算时长。把不确定性收在建场次这一次决定里，而不是散在事后逐条核对里。
- 时长 = 签退 − 签到，**向上取整至 0.5 小时**；按场次分段存明细，志愿者看得到自己的每一段。
- 结账是一条链，不是一次点击：**管理者核准**（通知本人）→ 本人于申诉截止
  （默认第二天中午）前确认或申诉 → 期满无人申诉由定时任务自动提交 → **归口部长审批锁定**
  （对外联络部由值班人处理，且要有盖章立项书，见第二节），通过即锁定，
  活动落「待录入志愿北京」（`vb_pending`）→ 管理者把时长录进志愿北京，在「审核」页签上传
  **志愿北京时长录入截图**（必传）并点「已录入」，活动才落「已完成」，无需他人审核，写审计。
  锁定满 3 天仍未确认，每天 9 点起提醒一次本活动管理者（`Activity.vb_reminded_on` 按天去重）。
  锁定后还要改，走解锁申请单，让部长知道改什么、为什么改；解锁通过一律回到「已结束」
  （不论此前是待录入还是已完成），截图作废，重新锁定后再录一遍。
  审批期间时长冻结，部长看到的和最终封的必须是同一份账。
- 岗位可以勾「可选劳务」：志愿者在确认时选劳务，平台就不给这个人记时长，导出到志愿北京
  的时长表里也不含他。
- 定位签到的管理端小地图用天地图瓦片，**由本站服务器转发**（`backend/routers/geo.py`）：
  浏览器直连时浏览器端 tk 靠 Referer 域名白名单，AdGuard 隐身模式之类的插件会改掉
  第三方 Referer，天地图一律 403、地图整块灰掉。现在浏览器只请求
  `/api/geo/tiles/{vec|cva}/{z}/{x}/{y}?t=令牌`，拿不到任何 tk。
  - tk：主路径是服务端 tk（`RUCVA_TIANDITU_TK_SERVER`），**部署时要在天地图后台把服务器
    公网出口 IP 登记进白名单**；没配时兜底用浏览器端 tk，由服务器带本站地址当 Referer。
  - 额度（每个 tk 每天 10000 次）：同一张瓦片只向天地图取一次，磁盘缓存 30 天
    （`rucva_tiles` 卷）；Redis 按天数真正打到天地图的请求（缓存命中不算），到九成记
    警告日志，到上限直接 503 不再请求上游；过期缓存在取不到新图时照旧拿出来用。
  - 防滥用：`<img>` 带不上登录令牌，所以管理者打开地图时先领一张瓦片令牌
    （`GET /api/geo/tile-token`，HMAC 签名、约 6 小时过期、不落库），前端快过期时自己
    重新领；瓦片接口先验令牌（缓存命中也验），无效或过期 401。

## 六、服装与学习材料

- **服装**（岗位设了「统一发放」才有）：一场活动**两个码**——一个领取、一个归还，
  直达 `/#/attire/{token}`。不做「同码扫两次」：领取和归还是两个物理动作，发生在活动的
  两头，现场常常是两张桌子。台账一人一条，另有批量登记与催领催还（可要求签收）。
- **学习材料**：挂在岗位上，文档自存（单文件 ≤50MB）或外链；视频不自托管，只存链接——
  大文件的上传成功率、带宽与备份代价都不划算。删记录即删文件，下载走一次性票据。

## 七、导出与留痕

- 三类 Excel 导出，都在活动管理页：**排班表**（Sheet1 活动概览列场次清单，其后每场次一个
  Sheet：姓名/学号/学院/手机号/场次时间｜岗位组/岗位/组长/服务地点/接受调剂｜签到状态/
  签退时间，再按需接上报名问卷的答案列。表按现场的组织方式排——先按岗位分块、组长排头，
  还没排上的沉到表尾红字标出，一眼看得出还差谁；有志愿者时长的活动额外附一张时长页）、
  **时长记录**（给志愿北京录入用，含身份证号，选择了劳务的人不在其中）、
  **报名问卷结果**（一人一行、一题一列，供部长们在 Excel 里筛选）。
  导出内容里的公式一律先拆掉——志愿者填进去的东西不能当公式执行。
- **审计留痕中心**：活动/场次/岗位增删改、发布、审批与转交、分配与强制分配、签到任务、
  导出、调分、违规登记、集成配置变更全记录（字段级 diff）。部分日志对志愿者可见，
  在活动页公示摘要；其余按活动级可见范围过滤。

## 八、外部对接适配层（backend/integrations/）

两个适配器：`msgcenter` 消息中心 / `sso` 统一身份认证。
参数存 `integration_configs` 表，「集成设置」页在线切换 `enabled=true`
即启用真实 HTTP 调用，改完生效、无需重启；**开关已开但必填参数为空时自动回落演示模式**。

演示模式行为：消息中心把模板消息落 `notifications` 表
（消息中心即收件箱，模板库 13 类场景），发送失败只标 `delivered=False`，不打断业务；
SSO 模拟「认证已通过」。

真实侧：`sso` 与 `msgcenter` 已备完整的 HTTP 实现。

志愿时长记在本平台、不对外回传。
